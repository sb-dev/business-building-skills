## 3. Method, sources and rejected alternatives

Start with the three accepted Level 5 prompts, whose distinct mechanisms already cover a complete business thesis. Preserve each prompt and its fixed facts exactly. Add a separate stress instruction and map every literal §23 exercise line to an observable response responsibility and a failure condition. Design five independent overlays per structure against the five exact original adversarial lines. Each overlay makes the tempting incorrect inference concrete, supplies the evidence that should defeat it, and states an adequate bounded response and repair. Negative controls are authored comparison material, not invented captured agent failures.

The JSON corpus is the structured source for these case designs and records the exact copied prompts and input identities. The three Markdown companions contain the complete readable cases, including their own inline base prompts and overlays; they do not require an unseen fixture to be useful. The verifier compares both representations, accepted prompts, literal specification lists, canonical selectors and arithmetic. Direct semantic review assesses what a structural check cannot: whether the stated evidence defeats the actual bad reasoning, whether an adequate response remains bounded, and whether protected decisions survive.

Sources actually accessed during Stage 16 were the governing and accepted repository files at the pinned `feat/bootstrap-3` head, its Git tree, Stage 15 commit metadata, and the head-to-boundary comparison through the GitHub connector. Earlier primary-source research remains attributed to its existing logs. It was not freshly revisited or counted as independent new evidence. No source-book text, empirical effect, current law, platform commission, customer result or competitor fact was newly asserted. Where a real action would need current external evidence, the case explicitly asks for that evidence and preserves the block on the affected commitment.
