# Stage 19 — Public README Design

**Version:** 1.0 · **Date:** 9 September 2026 · **Status:** Design complete

## Positioning

Primary line:

> Turn business ideas and operating problems into evidence-backed offers, acquisition systems and viable economic decisions.

Supporting message: Business Building Skills is an Agent Skills repository for forming, testing, growing and repairing businesses without treating persuasive tactics, vanity metrics or generated assumptions as evidence.

Do not market the repository as “five books turned into AI”. Source lineage belongs in a transparent section explaining that the books seeded candidate capabilities, were independently reconciled, and are not reproduced.

## Capability bullets

- frame customers, problems and value from traceable evidence;
- design deliverable offers, pricing and monetisation;
- model delivery, unit economics, capacity and cash;
- select acquisition/sales hypotheses using downstream quality;
- design falsifiable business experiments;
- diagnose constraints and preserve still-supported decisions;
- specialise behaviour through business-model Extension Packs.

## Quick start

Use L1A from Stage 15 because it is bounded, understandable and proves evidence classification + deterministic economics + experiment design without requiring external provider accounts. The README must show the exact prompt, expected input fixture and command/skill invocation only after those paths exist.

Do not fabricate a sample result before Stage 22 produces a real execution. Until then, canonical specs may contain the prompt but the public README should state implementation status accurately.

## Learn by Building

Present all 15 Stage 15 examples in five groups of three. Keep descriptions capability-focused. Every linked example must contain its exact prompt and synthetic/real classification. Level progression should be visible without requiring internal architecture knowledge.

## Product trust signals

README must state:

```text
facts / assumptions / synthetic fixtures stay distinct
calculations are deterministic where appropriate
external writes require authority
legal/tax/regulated conclusions are handed off
core works without Extension Packs or Pactwright
business quality is multidimensional
```

Avoid claims such as “guaranteed profitable business”, “optimal pricing”, “find product-market fit automatically”, or benchmark scores that have not been measured.

## Structure section

Before Stage 21, show only the actual bootstrap repository. After scaffolding, update it to actual directories. Do not document aspirational directories as if implemented.

## Stress tests and source lineage

Show Kakeibo, one-person FDE consultancy and Production Skills ecosystem as architecture stress tests, clearly separating designed fixtures from executed benchmarks.

Source lineage should name the five books as initial evidence inputs, explain capability-shaped extraction, copyright-safe independent expression and the current Stage 2 full-book access gaps. Do not use long quotes or proprietary examples.

## Exit

A new user can understand what the project will do, its evidence discipline, progression, limits and installation path without reading the bootstrap. Stage 21 will replace the minimal README only when the production structure exists.
