## 3. Benchmark taxonomy and case membership

Keep a small versioned collection of input, output and assessment files. There is no universal business evaluator, provider-specific runtime, CRM, customer database or one-number business score. The [structured case contracts](2026-09-12-stage-17-case-contracts.json) are an executable design input for later tooling, not a claim that production tooling already exists.

| Family | Membership | Purpose and gate |
|---|---|---|
| Deterministic design/product checks | D01–D10 | Validate fields, maths, scope, event/metric integrity, prompts, pack structure and later actual installation. Structural success does not grade business judgement. |
| Progressive primary cases | E01–E15, exactly 3 per original level | Retain every literal prompt, expected artefact, reference finding, negative control and protected decision. Grade level-appropriate depth and all triggered invariants. |
| Canonical stress tests | A/B/C base designs plus A01–A05, B01–B05, C01–C05 | Exercise the full three mechanisms and all 29 specified concerns/15 adversaries. These supplement rather than replace primaries. |
| Explicit §24 adversarial patterns | AD01–AD14 | Each original pattern has a complete minimal fixture and authored failing/adequate controls. Similar witnesses are cross-linked without deleting parent coverage. |
| Pack comparisons | S01–S09 and P01–P07 per implemented candidate/mode | Preserve eight independent candidates and advisory mode; define fit/non-fit, precedence, effects, metrics, incompatible cases and actual paired-run evidence. |
| Preservation/regressions | E10–E12 and affected cases; RG01–RG07 | Detect ungrounded broad changes and retain every real escape's old/repaired evidence permanently. AD09 is an explicitly synthetic discrimination rehearsal. |
| Installation/repository | Source, selective and clean external conditions | Separate source tests from actual consumer installation; verify complete local resources, discovery, prerequisites and reproducible entry points in Stage 24. |

All required cases remain in the full acceptance manifest. A scoped development rerun may select affected cases with an explicit reason, but it cannot be presented as full acceptance, omit a mandatory difficult case or change the release/maturity claim. All failures, blocks, invalid attempts and justified inapplicable findings remain visible.

The full accepted primary prompts are copied into the structured corpus byte-for-byte. Existing stress and pack fixtures retain exact source/version links; the full inline S01–S09 records are also copied unchanged. Later packaging must include the actual required fixtures/resources in their documented distribution location; a consumer task must not secretly reach back into this bootstrap checkout. No installation path, executable command or auto-discovery protocol is advertised as implemented by this design.

Use a separate raw run-state record such as succeeded, failed, blocked or not-run for execution bookkeeping. Conformance tables use only PASS, FAIL, BLOCKED and justified NOT APPLICABLE. Never map not-run to PASS or treat a drafted shell command as execution. For a deterministic comparison, compare actual numeric identities with declared tolerances; for semantic reasoning, inspect the actual argument, evidence and effect. A source file's existence or a presence-only string check proves neither.

Report per-case, per-dimension and per-effect findings, exact required/actual counts, calculation discrepancies and actual preservation violations. Report total attempts and all failed/blocked attempts separately from judged outputs. Measured latency/tokens/cost are optional diagnostics only when actually exposed and comparable. Do not turn pass-count arithmetic into a universal commercial-quality score. A single paired observation supports only that task/version/configuration; any broader rate or superiority claim requires its own prespecified repeated design and uncertainty analysis.
