# Business Building Skills — Repository and Contracts Specification

**Version:** 1.0 · **Status:** Target repository design · **Date:** 9 September 2026

## Target structure

```text
README.md
LICENSE
CONTRIBUTING.md
CHANGELOG.md
docs/01-...06-*.md
docs/research-logs/
skills/
  business-build/
  business-grow/
  business-evaluate/
  business-pack-author/
examples/levels/1..5/
benchmarks/
tests/
extension-packs/          # only implemented/researched packs as specified
integrations/             # optional provider adapters only
.github/                  # CI when justified
```

Do not create a CRM, customer database, analytics warehouse, billing/payment system, ad platform or accounting engine. Do not create empty symmetry directories.

## Skill contract

Each `skills/<id>/SKILL.md` states mission, trigger/use cases, required inputs, evidence policy, workflow, commands, output responsibilities, tool boundary, preservation, failure modes and acceptance. It must be self-contained after selective installation.

Optional skill-local surfaces:

```text
commands/*.md
references/*.md
scripts/*
evals/*
```

Create only when used. Cross-skill references must not require source-repository-relative files that disappear during selective install; duplicate only small stable contracts where necessary or package shared references explicitly according to the final installer.

## Command contract

Every command defines purpose, inputs/evidence, allowed assumptions, output/artefact mutation, allowed mutation scope, preserved dependencies, forbidden behaviour, deterministic/external tools, approval/professional gates, failure states and acceptance checks.

Commands never imply external writes. A provider-specific integration may implement a read/draft/write operation only under Stage 11's handoff contract.

## Deterministic scripts

Use a lightweight, widely available runtime selected during implementation. Scripts own arithmetic/validation only: economics, cash schedules, funnel consistency, frontmatter/pack/example/repository checks. Keep formulas testable with synthetic fixtures. Do not encode legal/accounting judgement or business thresholds as universal constants.

## Extension Packs

Target:

```text
extension-packs/<pack-id>/
├── PACK.md
├── references/     # optional
├── examples/
└── evals/
```

PACK metadata includes version, maturity, applicability, activation/non-activation, core effects, economic/capacity semantics, precedence, showcase exact prompt and eval coverage.

## Examples

Five levels × three primary examples. Each primary example contains README/context, exact prompt, synthetic/real classification, expected capability coverage and relevant fixture files. Do not commit personal/customer data.

## Benchmarks

Case directories contain exact prompt, fixtures, immutable facts, expected deterministic results, semantic properties, forbidden behaviours, mutation scope and rubric. Results generated by real agents are stored separately from expected contracts and include model/provider/date where permitted.

## Installation

Core skills are selectively installable using the Production Skills family mechanism chosen at implementation. A clean consumer project must run without a checkout of this repository. Provider SDKs are optional; missing providers produce manual handoffs.

Document runtime prerequisites, supported Agent Skills consumers and any licence obligations. Installation smoke tests use a temporary clean directory and verify discovery plus skill-local references/scripts.

## CI / technical acceptance

CI should run repository validation, deterministic tests, prompt/pack metadata checks and clean-install smoke tests. Semantic agent evals may be separate/manual/provider-gated if they require model access; CI must not fabricate a pass when no agent execution occurred.

## Source integrity

Research logs may cite books/web sources but skills should encode independently expressed capabilities. Do not redistribute substantial copyrighted source text, proprietary examples or unverified book content. Stage 2 source gaps remain visible until closed.
